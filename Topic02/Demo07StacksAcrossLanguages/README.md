# Demo 07 — A stack in Java, C++, C# and Python

## Problem statement

Implement the same stack abstract data type in four languages. Push 1, 2 and 3,
look at the top, traverse the stack from top to bottom without removing
anything, and finally pop all the elements. Keep the interface separate from its
implementation.

This corrects and extends the old Java `ArrayStack` and the C++ and C# `CA2`
material. The Python version adds a comparison between static and dynamic
typing. Java is the course version; the other languages are optional material
for comparison, and each one is self-contained in its own subdirectory.

## Prerequisites

From Topic 1 you need interfaces, generics, references, arrays, exceptions and
inner iterators, and from Topic 2 the stack contract. Read
“Stacks: last in, first out” and “Choosing the top of a stack” in the
presentation before running this example.

The optional C++ version uses templates, references, pure virtual functions, STL
iterators and automatic resource management. The C# version uses enumerators
generated by the compiler, and the Python version uses Python's built-in reverse
iterator. These details are explained below.

## Common behaviour

All four versions keep duplicates, report the number of elements rather than the
capacity, reject `pop` and `peek` on an empty stack, and traverse in LIFO order
without changing which elements are stored. Each traversal has its own state, and
insertion can make the storage grow.

| Operation | Java / C++ | C# | Python |
| --- | --- | --- | --- |
| Insert at top | `push(item)` | `Push(item)` | `push(item)` |
| Remove top | `pop()` | `Pop()` | `pop()` |
| Observe top | `peek()` | `Peek()` | `peek()` |
| Number of elements | `size()` | `Size()` | `size()` |
| Test emptiness | `isEmpty()` | `IsEmpty()` | `is_empty()` |

| Property | Java | C++ | C# | Python |
| --- | --- | --- | --- | --- |
| Interface | `Stack<E>` | `Stack<T>`, abstract class template | `IStack<T>` | `Stack[T]`, generic abstract base class |
| Implementation | `ArrayStack<E>` | `ListStack<T>` | `ArrayStack<T>` | `ArrayStack[T]` |
| Storage | Growing array | `std::list<T>` | Growing array | Built-in list, used as a growing array |
| Empty pop / peek | `NoSuchElementException` | `std::underflow_error` | `InvalidOperationException` | `IndexError` |
| Capacity parameter | Default 10; nonnegative initial capacity | Managed by list | Default 10; nonnegative initial capacity | Managed by list |
| Growth | Double the array, or grow zero to one | Allocate another node | Double the array, or grow zero to one | List manages its capacity |
| Traversal implementation | `Iterable<E>` / `Iterator<E>` and enhanced for | STL `const_iterator`, `begin/end` and range-based for | `IEnumerable<T>`, `IEnumerator<T>` and `yield return` | `__iter__` delegates to `reversed(list)` |
| Type checking | Static, with erased generic parameters | Static, with template instantiation | Static, with runtime generic type information | Dynamic; annotations support separate static analysis |

The capacity policy is now the same in Java and C#: the old fixed-capacity Java
implementation has been replaced by a growing array, as in C#. A negative initial
capacity is rejected with a simple conditional. Zero is valid and grows to one on
the first insertion. In this example, C++ and Python do not offer a capacity
argument. An allocation can still fail if resources run out.

## Java: explicit iterator state and array growth

`data[0..size)` holds the active elements and `size - 1` is the top. When the
array is full, `push` grows it; it then writes the new reference and increments
`size`. The capacity doubles, and a capacity of zero grows to one. This Java
example does not deal with extremely large capacities. `Arrays.copyOf` copies
the existing references into a larger array before the field is replaced.

`pop` checks that the stack is not empty, decreases `size`, saves the reference
and clears the cell that is no longer used, so that the array does not keep
removed objects alive. `peek` reads the same top cell without changing `size`.
`null` elements are allowed, so `null` cannot be used to signal an empty stack.

The constructor allocates an `Object[]` and stores it as `E[]` through a single,
local cast with the warning suppressed, because Java cannot allocate
`new E[capacity]` directly. The array stays private, and accessing elements
needs no further cast.

`StackIterator` keeps a position that starts at `size - 1`. Each call to
`next()` returns one element and decreases that position, and calling it on an
exhausted iterator throws `NoSuchElementException`. The default iterator
`remove` is not supported.

## C++: STL iteration and value semantics

`Stack<T>` declares the stack operations as pure virtual functions, together with
a virtual destructor. `ListStack<T>` uses the front of `std::list<T>` as the top.
The client creates an automatic local object and uses it through a `Stack<int>&`
for the ADT operations. The list manages its nodes without any explicit `new` or
`delete`.

`push(const T&)` avoids copying the parameter, but storing the element still
copies it into a node. `peek() const` returns a `const T&`, which avoids a copy
and prevents assignment through that reference. `pop` copies the value before
destroying its node. This teaching version requires element types that can be
copied; it does not cover move-only values, or strong exception guarantees when
copying an element can throw.

Traversal uses the STL protocol directly. `ListStack<T>::const_iterator` is an
alias for `std::list<T>::const_iterator`; `typename` marks a nested type whose
meaning depends on the template parameter `T`. `begin()` refers to the top, and
`end()` is the position just past the bottom. A const iterator lets you read
values without modifying them, and `cbegin()` and `cend()` give the same
read-only pair.

```cpp
for (const auto& value : storage)
{
    std::cout << value << '\n';
}
```

The range-based loop uses `begin` and `end`, compares positions, dereferences
with `*` and advances with `++`. The standard algorithms work with the same pair:

```cpp
int total = std::accumulate(storage.begin(), storage.end(), 0);
```

Include `<numeric>` for `std::accumulate`. There is no separate `hasNext`/`next`
interface and no traversal object allocated on the heap. Reaching `end()` means
that the traversal is over; dereferencing `end()` is invalid, rather than an
operation that throws an exception. Each copy of an iterator has its own
traversal position.

Traversal belongs to the concrete iterable container, and the abstract `Stack<T>`
keeps only the ADT operations. This allows standard iterator types without tying
every stack implementation to a particular STL storage type. Do not change the
stack during a traversal. The stack must outlive its iterators and any references
returned by `peek()` or by dereferencing an iterator.

Copying a C++ stack copies its list nodes, and copies the values according to the
copy semantics of `T`, so the copy has its own container storage. If `T` is a
pointer type, copying the pointer does not copy the object it points to.

## C#: iterator state generated by the compiler

C# allows `new T[capacity]` directly. Growth doubles the capacity (or turns zero
into one), checks for integer overflow, allocates the new array and copies the
active elements. `Pop` clears the cell that is no longer used with `default(T)`,
which is `null` for reference types and zero for integers.

The generic `GetEnumerator()` loops backwards and uses `yield return`. The
compiler creates an enumerator that remembers the loop position between calls.
The non-generic `IEnumerable` implementation delegates to this method.

The public iterator protocol uses `MoveNext()` to advance and `Current` to read.
`MoveNext` returns `false` once the enumerator is exhausted. This differs from
Java's `hasNext`/`next` protocol, even though `foreach` produces the same
traversal. The body of the generator starts running on the first call to
`MoveNext`, not when `GetEnumerator` is called.

## Python: the same contract with dynamic typing

`Stack[T]` combines `ABC` and `Generic[T]`. `@abstractmethod` requires a concrete
subclass to supply the operations. `TypeVar("T")` links the element type accepted
by `push` with the type returned by `pop`, `peek` and iteration. `ArrayStack[T]`
implements that contract with a list field, `_data`, which is private by
convention.

Python is both strongly and dynamically typed. Values have types at run time, and
annotations neither change how calls are dispatched at run time nor enforce the
generic argument. A static analyser can reject this client code before it runs:

```python
stack: Stack[int] = ArrayStack[int]()
stack.push("hello")  # Deliberate static type error.
```

Without a checker, the example implementation would accept the string. At run
time Python checks the operations that are actually performed, not this
annotation. By contrast, `1 + "hello"` raises `TypeError`: dynamic typing does
not mean that arbitrary implicit conversions are allowed.

`list[T]` already provides a growing array, so the implementation leaves the
allocation to it. `append` inserts at the end, `pop` removes from that end, and
index `-1` reads it. A simple conditional rejects access to an empty stack. This
keeps the focus on the ADT instead of reproducing Python's internal memory
management.

`__iter__` returns `reversed(self._data)`, Python's built-in reverse iterator. It
starts at the last element of the list, which is the top, without copying or
removing elements, and each call creates an independent iterator. `iter(stack)`
obtains the iterator and `next(iterator)` advances it; once it is exhausted it
raises `StopIteration`, which Python's `for` loop handles automatically. `None` is
a valid value when the chosen annotation allows it, for example
`ArrayStack[int | None]`; it does not mark the end of the traversal.

## Mutation and copying

None of these stacks is thread-safe. Do not modify a stack during a traversal.
No iterator removes elements, takes a snapshot or checks for concurrent changes.

In Java, C# and Python, assigning a stack variable to another shares the same
stack object, and elements of reference types are shared too. In particular,
copying references into a larger array does not clone the elements. Compare this
with C++, where copying a `ListStack<T>` copies its values. The interfaces make
no attempt to hide these differences between languages.

## Complexity

For n stored elements, `peek`, `size` and the emptiness check take O(1). A full
traversal takes O(n), and the iterator state is O(1) in every version. On the
linked stack, `push` and `pop` do O(1) work in the container, plus the cost of
allocation and of copying the element. On a growing array, `push` is amortised
O(1), with O(n) work whenever the storage grows. In Java and C#, `pop` is O(1).
Python's built-in list manages its own resizing, so inserting and removing at
the end are amortised O(1) under its usual dynamic-array implementation.

Java and C# keep the allocated capacity after pops, the C++ list releases
removed nodes, and Python decides for itself how much spare capacity to keep.
The comparison of costs assumes that operations on elements take constant time;
copying an arbitrary C++ value of type `T` can cost more than copying an object
reference.

```

```

runners for the other languages are separate.

## Expected output in every language

```text
Initial stack: size = 0; empty = true
push(1): size = 1; top = 1
push(2): size = 2; top = 2
push(3): size = 3; top = 3
Traversal from top to bottom: 3 2 1
After traversal: size = 3; top = 3
pop(): 3; size = 2; top = 2
pop(): 2; size = 1; top = 1
pop(): 1; size = 0; top = (empty)
Reuse with push(9): size = 1; top = 9
pop(): 9; size = 0; top = (empty)
```

The traversal leaves all three elements in place, and the pops that follow show
that it does not consume the stack. The tests also cover access to an empty stack,
duplicates, several insertions and removals, reuse, independent traversals and
exhaustion. Java and C# add explicit cases for zero and negative capacities. C++
checks range-based traversal, the standard algorithms and independent copies of
the container. Python checks `None`, zero and shared objects.

## Validation of this revision

This revision was validated with Java 17, GCC in C++17 mode, Mono C# 6.8 and
Python 3.12. All four main programs produce the output above, and all four
behaviour suites pass. Java and C++ compile with all configured warnings treated
as errors; the C# validation uses the Mono runner rather than the .NET 8 SDK.

The Java and C++ checks cover independent native iterators, exhaustion and the
fact that traversal leaves the membership unchanged. C++ also exercises
`std::distance`, `std::accumulate`, `std::find` and `std::count`. C# checks both
generic and non-generic enumeration, independent disposable enumerators and
exhaustion. Python's `unittest` suite, from the standard library, checks its
built-in reverse traversal.

## Experiments

1. Push a duplicate and check that both occurrences appear in the iteration and
   in the pops.
2. Create two iterators and advance only one of them, to see that their
   positions are independent.
3. Compare Java's explicit iterator index, the enumerator that C# generates, the
   STL iterator operations in C++ and Python's built-in reverse iterator.
4. Copy a C++ stack and then pop the copy. Compare this with assigning a second
   variable to the same Java, C# or Python object.
5. Ask a Python static analyser to check a deliberately incorrect `push`, and
   then tell that diagnostic apart from what the unannotated program allows at
   run time.
