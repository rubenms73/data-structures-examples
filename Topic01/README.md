# Topic 1 — Classroom examples

Data Structures · University of Oviedo

Fourteen self-contained Java projects accompany the Topic 1 presentation. Each folder contains its own `ds` package and an `app.Main` test program. The examples do not share source folders, compiled classes or external libraries.

## Open one example

1. Choose a folder below, for example **Demo05Movies**.
2. Open **that example folder** in VS Code, with JDK 17 or newer and the Extension Pack for Java.
3. Open `src/app/Main.java` and select **Run** or **Debug** above `main`.

You can copy a single example folder somewhere else and it will still work. Its README gives the slide references, the commands, links to the classes and the expected output. When two examples need the same class, such as `FixedMyArray`, each one has its own copy.

On macOS or Linux, from an individual example folder:

```sh
bash run.sh
bash run.sh test
```

## Run from the Topic01 folder

The optional launcher builds each project on its own:

```sh
bash run.sh list
bash run.sh Demo05Movies
bash run.sh all
bash run.sh test
```

Do not merge the `src` folders into a single Java project: names such as `app.Main` are repeated on purpose. Each example has its own `bin` directory and VS Code configuration.

## Demonstrations

The introductory interface and array examples use ordinary arrays and the local `MyArray` interface. Example 08 uses a linked list only to collect the values generated by its iterator. The `Collections` demo on lists and sets has moved to [Topic 4, Demo04Collections](../Topic04/Demo04Collections/README.md), where its prerequisites on collections have already been covered. Example 14 is a closing exercise using `Collection` and `AbstractCollection`, to be studied once those interfaces and the iterator operations have been explained. The examples are numbered consecutively from 01 to 14. Start with the basic interface and array examples, then comparison and iteration. The functional-interface and wildcard examples belong to the appendix, so study them after the corresponding theory.

For a step-by-step test of `Predicate`, `Supplier`, `Consumer` and `Function`, see [Demo11FunctionalOperations](Demo11FunctionalOperations/README.md). Its README sets out the problem, the operation of each interface and the expected output.

## Relationship to the slides

- `Rational` includes the observer operations used in the main sequence of slides. These examples do not implement the extended interface with factory and reduction operations from the appendix. Neither of the two representations has mutators.
- `MyIntArray` and its three classes keep the hierarchy shown in the presentation. The abstract class supplies only `isEmpty` and `contains`; each concrete class manages its own storage and implements `add`.
- `FixedMyArray` provides fixed-capacity storage in an ordinary array. It implements the local `MyArray` interface without relying on the Java Collections Framework.
- `Maximum` and `FlexibleMaximum` both use `max(T[] values, Comparator<? super T> order)`. The maximum example uses this signature from the start, and the wildcard example explains why a comparator for a supertype can be reused. There are two separate classes so that each project stays self-contained.
- `Movie` is an extra example that leaves the presentation unchanged. Its titles and ratings are fictional. Its natural order is chronological, with title and rating as tie-breakers, and equality uses the same three fields.
- The cost example counts the additions made while traversing an array and contrasts them with direct array access. It does not introduce linked lists.

The deliberate compilation errors are commented out. Uncomment one at a time, read the error, and undo the change before you continue.

## Windows

Open a terminal in this folder (PowerShell, Command Prompt or the VS Code
terminal). Install JDK 17 or newer and put its `bin` directory on `PATH`;
`java -version` and `javac -version` should both work. No Bash, WSL or Git Bash
is required.

```powershell
.\run.cmd list
.\run.cmd all
.\run.cmd test
```

Select a demo by passing its name from `list`, for example `.\run.cmd Demo01Rational`.
The launcher sets its own working directory and copes with paths containing
spaces and with any bundled JAR libraries. It runs on Windows PowerShell 5.1,
which comes with Windows, and `run.ps1` also works with PowerShell 7. The VS Code
**Run** and **Debug** buttons are still available when the example folder is open.
